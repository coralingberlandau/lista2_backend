## Lista 1 compared with Lista 2

Lista 1 already had accounts, lists, sharing, pictures and backgrounds. Lista 2 keeps all of that and rebuilds what is behind it.

| Area | Lista 1 | Lista 2 |
|------|---------|---------|
| **Access control** | Login with JWT, sharing with Read-Only or Full Access | Everything requires a login unless it is deliberately public, and permissions are checked on the server for every list, picture and profile request |
| **Sessions** | Access token only | Short-lived access token (25 minutes) plus a 90-day **rotating refresh token**, so people stay logged in safely |
| **Sign-up** | The app asked for first and last name as well | Only a username, an email and a password are required; names are optional |
| **Passwords** | Basic registration | Password strength rules, and a **single-use reset link that expires after one hour** |
| **Email** | SendGrid | **Brevo**; if an email cannot be sent, the API says so instead of pretending it worked |
| **AI ideas** | Generated by the backend with OpenAI | No AI inside the API any more: ideas come from **Google Gemini** through a Netlify function, so no AI key lives on this server |
| **Pictures** | Uploaded and re-indexed in separate steps | Saved with the list in **one all-or-nothing step**, checked to be real JPEG, PNG or WebP files (8 MB, 40 megapixels), and deleted from disk when no longer needed |
| **Lists** | Needed items | A list can be just a title. Every list reports which rows have a picture (`picture_rows`) |
| **Configuration** | Settings in code, debug on | All settings and keys come from environment variables; debug is off by default; no secrets in the repository |
| **Logs** | Plain logs | Tokens, passwords and `Authorization` headers are redacted |
| **Quality** | No automated tests | **73 automated tests** and a dependency audit before every release |
| **Hosting** | Render's free tier, which had to be woken up before the app could be used | PythonAnywhere with a persistent disk for the database and pictures; the app is not put to sleep after inactivity |

## What the API does

| Capability | In short |
|------------|----------|
| **Create and save lists** | Lists of text items, with optional pictures on any row. A list can be a title alone. Deleting a list only hides it, so nothing is lost by accident |
| **Organize and reuse** | Update lists any time, tick items off, then uncheck all to use the list again |
| **Share with permissions** | Share a list with other people as **Read-Only** or **Full Access**. The server enforces it on every request |
| **Pictures** | Attach a picture to a row. Pictures are saved together with the list, all or nothing, and checked to be real pictures |
| **Personalize** | Each person keeps their own background |
| **Accounts** | Registration, login, session renewal, a private profile and a safe password reset by email |

## How the app uses the API

The screens belong to the frontend; the API supports them as follows.

1. **Sign Up and Login**  
   - Registration with just a username, an email address and a password (`/register/`); first and last name are optional.
   - Login for existing users with username and password (`/login/`); sessions renewed with `/token/refresh/`.  
   - Forgot / change password with the emailed link (`/reset_password_request/`, `/reset_password/`).

2. **List Overview**  
   - View all lists (personal and shared) (`/grouplists/by-user/{id}/`).  
   - Create and manage new lists (`/listitem/`).  

3. **List Creation**  
   - Add items and pictures; the pictures are saved together with the list when the person presses Update List (`/listitemimages/sync_images/`).  

4. **Edit and Share Lists**  
   - Modify list details and tasks.  
   - Reordering rows, ticking items and deleting an item (a swipe, followed by Undo for 5 seconds) happen on the screen only: nothing is sent to the API until the person presses Update List, so the API did not change for the refreshed app design.  
   - Share lists with additional users and set permissions (`/get_user_info/{email}/`, `/grouplists/`).  

5. **Settings**  
   - Edit your profile (`/user/{id}/`) and choose a background (`/customizations/`).
